## 1. 产品定位与核心价值主张

### 1.1 产品定义
**Chillin** 是一款兼具**极致轻量、数据绝对可控、全端原生沉浸美学、双向知识网络与 AI 记忆回响**的个人跨端「数字花园（Digital Garden）」。它打破了传统笔记软件（依赖臃肿打包、打开慢、层级僵死）与碎片记录工具（易记难寻、缺乏沉淀、信息孤岛）之间的壁垒，为用户提供一个**随手记录即成脉络、长久沉淀生生不息、双向链接织就网络、往期记忆可被 AI 唤醒**的私人心智空间。

### 1.2 核心价值金字塔
```
             ▲
            / \     【顶层：心智共鸣与记忆觉醒】
           /AI \    AI 记忆回响（RAG 全域联想、可折叠回响卡片、记忆来源双向交互跳转）
          / 回响 \
         /--------\ 【中层：知识编织与常青生长】
        / 结构沉淀 \ 常青专栏资产台、[[双向链接]]与反向引用、Notion 级周记、单行极简阅读
       / 与网络交织 \
      /--------------\ 【底层：极速捕获、全端工效与自主安全】
     / 随手记 / IDB离线 \ 0依赖极速秒开、手势灯箱、每日心绪打卡、定期备份守卫、单RTT增量同步
    /____________________\
```

* **零摩擦捕获 (Zero-Friction Capture)**：随手记 1 秒内完成记录，支持链接卡片与图片多图预览；**v2.5.97 起不再解析外链标题/封面**（第三方抓取对 Cloudflare 出口长期不可用，故整体移除该能力），无排版心理负担。
* **常青生长与知识网络 (Evergreen Network)**：引入数字花园三阶生命周期（萌芽/生根/常青），支持 `[[双向维基链接]]` 与反向引用（Backlinks）上下文高亮反查，让碎片记录自发生长为知识森林。
* **绝对自主与备份守卫 (Data Sovereignty & Guard)**：存储引擎升级至 IndexedDB 异步大容量接管，彻底突破 5MB 限制；内置一键打包全量 ZIP 备份与定时备份守卫提醒，真正做到数据永不丢失、随时可带走。
* **去 AI 感的 Apple HIG 质感 (De-AI Craftsmanship)**：全站落地 Konsta iOS / Apple HIG 规范，自然纸感暖灰底色（`#F8F9FA`）、全矢量精巧 SVG、半屏抽屉（Bottom Sheet）与细致微动效，洗尽 AI 模板的浮躁廉价感；v2.5.116 起强调色唯一化为 `#007AFF`，主表面去掉 1px 硬边框改两层柔和弥散阴影（`--surface-radius` 26px），热力图色阶收敛为 systemGreen 透明阶；v2.5.117 起补上首屏柔光渐变（低透明度蓝绿 `radial-gradient`）与 40px 大标题、20px+ 卡片间距的留白节奏；v2.5.118 起清 UI 工程债——顶层层级收敛为 `--z-nav` / `--z-modal` / `--z-toast` / `--z-auth` / `--z-alert` 五枚令牌（并修掉「图片预览关闭按钮压住确认弹窗」的层级错误）、`transition: all` 全量改为显式属性列表、模糊层由 46 条声明减到 41 条、`.mobile-bottom-nav` 的 11 处定义合并为 10 块（合并前后在多组主题/PWA 上下文里逐属性比对 computed style）；v2.5.119 起补上应用级深色主题——`html[data-theme]` 跟随系统或手动切换、head 内联脚本首帧前落属性，灰度字面量收敛为 `--label-rgb` / `--neutral-rgb` 分量令牌（131 处自动随主题反转），并覆盖导航/卡片/文字/输入框/悬浮态五类主表面。

### 3.1 核心模块深度拆解

#### ① 常青主题资产台与数字花园生长系统 (Evergreen Topic Shelves)
* **超越传统标签分类**：引入真正的数字花园哲学，将用户的知识按生长阶段沉淀为：
  - **🌱 萌芽期 (Seedling)**：零散碎片、刚记录的想法；
  - **🌿 生根期 (Budding)**：正在扩充、多次迭代的主题；
  - **🌳 常青期 (Evergreen)**：体系成熟、可长期沉淀复用的核心专栏。
* **专栏全览抽屉 (All Topics Sheet)**：支持多级层级穿梭与返回，去除了虚假主题指标与 AI 感打分套话，基于全域真实字数与关联密度算法计算成熟度。

#### ② Daily Spark 每日心绪与时光偶遇
* **5 档精选心绪打卡**：精选沉静、愉悦、专注、疲惫、焦虑等 5 档自然心绪，轻触即完成当天情绪锚定。
* **轻启发提问 (Daily Spark Prompt)**：每日推送一条触发思考的极简提问，启发自省与灵感捕获。
* **时光偶遇 (On This Day / Time Capsule)**：智能从历史记录中唤醒过往的这一天，让沉睡的记忆与当下产生跨时空对话。
* **人性化 04:00 换日机制**：符合现代创作者与夜猫子作息规律，午夜到凌晨 4 点前的记录自动归入前一日夜间心绪，配合午夜跨天与后台切回自动感知，避免界面状态滞后。

#### ③ 双向维基链接与反向引用 (Bi-directional Wikilinks)
* **维基语法支持**：正文中直接输入 `[[笔记标题]]` 或 `[[目标|别名]]`，即可渲染为原生质感的可交互胶囊药丸（Wikilink Pill）。
* **反向引用反查 (Backlinks)**：任意笔记底部自动聚合所有引用了当前文章的周记、笔记与随手记条目，并附带包含关键词 `<mark>` 高亮的上下文切片，实现真正的个人第二大脑网状连接。
* **严格安全性保障**：内置防 XSS 转义与防二次转义机制，无缝嵌入 Markdown 渲染流程。

#### ④ 存储引擎跃迁与数据备份守卫 (Storage & Backup Guard)
* **IndexedDB 异步大容量接管 (`db.js`)**：前端数据底座从容量严重受限（5MB）的同步 `localStorage` 全面升级为异步 IndexedDB 引擎，彻底消除大型小说、海量批注和离线历史导致的 `QuotaExceededError`，并保留透明降级兜底。
* **一键全量备份导出**：一键打包生成结构化全量 ZIP 压缩包（完整 JSON 元数据、标准化 Markdown 文档，并合并服务端 `/api/export` 的阅读进度、云端书库元数据、健康打卡与 Bot 档案；包内 README 说明范围），支持本地保存与 Resend 邮件云端直发。R2 里的图片二进制与书籍正文不塞进 JSON，避免备份包被单本 20MB 的正文撑爆。
* **定期备份守卫 (Backup Guard)**：用户可设置自定义备份周期（7天 / 14天 / 30天），系统实时监测备份健康度，顶栏与账号面板直观展示状态徽章（良好绿色 / 过期橙色），并在超时未备份时通过温和的应用内弹窗提醒用户打卡归档。

#### ⑤ 系统级 Web Push 通知通道加固
* **动态 Tag 与 `renotify`**：重构通知发送通道，采用动态标签避免旧通知被吞，支持静默就绪与即时震动提醒。
* **全生命周期状态感知**：在「账号与安全」面板中提供通知权限实时状态徽章（已开启 / 未授权 / 不可用），并内置「发送测试通知」验证通道，附带超时保护与双通道降级。
* **订阅同步失败不再静默（v2.5.166）**：浏览器订阅上传服务器失败时，状态徽章改为「待同步」并给出「重试同步」，不再无条件提示“已成功开启”；失败标记保留到重试成功或退出登录。

#### ⑥ 沉浸式单行极简阅读器 (Full-Bleed Immersive Reader)
* **单行导航栏深度整合**：将书名居中、目录侧边栏开关、主题切换全面整合进 54px 的单行顶部毛玻璃导航中。
* **全对称 Chevron 与光学对齐**：使用标准 SF Symbols / Lucide 矢状几何路径 `<path d="M15 19l-7-7 7-7"/>`，配合 `translateY(-0.5px)` 黄金中轴对齐，消除移动端点击蓝色/绿色外边框。
* **云端阅读进度双向同步（v2.5.101 强化）**：打开书时按客户端时间戳做**双向合并**——云端更新则对齐、本地更新则回推；服务端以 `WHERE excluded.client_ts >= reader_progress.client_ts` **拒绝过期写入**，两台设备同时在线也不会把进度拉回旧位置；断网期间的进度进入本地队列，联网后自动补推。
* **云端书库（v2.5.100）**：TXT 正文不再只锁在本机 IndexedDB——导入时自动推送至 R2（`books/<userId>/<sha256>.txt`），换设备打开书架即可看到带 ☁️ 标记的「点击下载到本机」卡片，点开即下载入本地书架并直接进入阅读；本地删除会同步写入云端软删墓碑。

## 4. 全端重构与产品体验护城河

通过持续的底层视觉与交互工程演进，Chillin 彻底洗尽了 AI 生成界面的廉价套路，全面对标 Apple HIG 与 Konsta iOS 原生触感：

### 4.1 彻底的「去 AI 化」重构 (De-AI Overhaul)
* **纯粹纸感登录页重构**：完全推倒早期模板化 AI 登录页，重构为居中极简拟真纸质卡片，引入纯净品牌 Emblem 徽标，增加密码显隐切换，移除一切冗余副标题与夸张插图。
* **账号与安全半屏抽屉 (Bottom Sheet)**：依据 Konsta iOS 规范重构账号面板，消除顶部生硬白线，采用无边框胶囊关闭按钮与分组卡片布局。
* **全局高光与毛刺边框清洗**：彻底清除所有卡片、Tab 选项卡、按钮上的刺眼外发光、蓝色光晕与高对比度边框，以柔和的半透明阴影（`rgba(0, 0, 0, 0.04)`）营造呼吸感。

### 4.2 移动端工效学优化 (Mobile Ergonomics)
* **全屏手势图片灯箱 (Lightbox Gallery)**：点击随手记图片弹出全屏沉浸画廊，支持多图滑动切换、双指缩放、原图下载与下拉手势关闭。
* **半屏抽屉 (Bottom Sheet) 交互**：全面淘汰居中 Modal 弹窗，新建随手记、批注、专栏全览均采用大拇指热区友好的半屏底部抽屉。
* **软键盘智能避让与顶底栏联动**：唤起虚拟键盘时，底部导航栏（Bottom Nav）与悬浮按钮（FAB）自动平滑淡出，视口回弹平顺，防止遮挡光标视线。

## 5. AI 记忆回响系统 (RAG) 核心闭环与架构

Chillin 拒绝无意义的通用泛化聊天，专注打造基于个人历史数据的**“私人第二大脑记忆回响”**：

```
[ 用户提问 / 代词追问 ]
        │
        ▼
[ 多轮代词分析器 ] ──(抓取上下文指代核心名词)──┐
        │                                      │
        ▼                                      ▼
[ 自然语言时序解析 ]                        [ 关键词分词与停用词过滤 ]
(如: "上周的随手记")                                  │
        │                                      │
        └──────────────────┬───────────────────┘
                           ▼
              [ 边缘 RAG 混合召回引擎 ]
     ┌─────────────────────┼─────────────────────┐
     ▼                     ▼                     ▼
 [随手记流]              [周记/笔记]           [提示词库]
     └─────────────────────┬─────────────────────┘
                           ▼
              [ BM25/多特征时序加权排序与截断 ]
                           ▼
              [ 提示词注入 + DeepSeek / Workers AI ]
                           ▼
            [ 流式 SSE 打字机响应 + 可交互溯源卡片 ]
                           │
                           ▼
           [ 用户点击卡片 ➔ 页面平滑回跳原始条目并高亮闪烁 ]
```

### 5.1 体验核心亮点
1. **短多轮代词继承**：当用户在连续对话中追问“它什么时候记的？”或“还有更详细的吗？”，系统自动溯源上一轮对话的核心实体并入检索，消除指代消解失败的缺陷。
2. **提示词全域入库**：Prompts 库作为一等公民参与 RAG，用户可直接询问“我以前写过什么翻译提示词”，AI 会提取精准卡片供即时复用。
3. **事实溯源与闭环回跳**：AI 回答底部的引用卡片支持点击。点击后，AI 弹窗自动淡出，界面直接平滑滚动定位到原随手记、周记、笔记或收藏，并触发 CSS 脉冲高亮；若目标落在 100 条/60 条分页窗口之外，或被年/月筛选隐藏，会先扩窗/复位筛选再定位（v2.5.167），实现由“AI 生成”到“原汁原味事实证据”的无缝闭环。

## 6. 技术架构、存储引擎与工程化治理

### 6.1 前后端技术拓扑与 Zero-Build 哲学
* **前端架构**：原生 HTML5 + Vanilla CSS + 原生 ES Modules（**Zero-Build 零构建打包哲学**）；v2.5.172 起只在 `<head>` 用 `modulepreload` 预热入口 `app.js`（与 script src 同 `?v`）；v2.5.173 起 `reader`/`upload`/`prompts` 改为路由级 `import()`（`feature-loader` 单例 Promise，首击兜底重放），模块 SW 改 stale-while-revalidate（精确缓存命中先返回、后台 `waitUntil` 刷新）；v2.5.174 移动底栏由通栏改为左右 12px、22px 圆角的悬浮胶囊 dock（同款毛玻璃、选中项浅色胶囊，并与阅读器底栏统一）；v2.5.175 底栏在向下滚过 96px 后平滑下移收起、向上 6px 即恢复，顶部 48px 内始终显示；实测给 4/12 个业务模块加 modulepreload 会抢 249KB CSS 的带宽、拖慢 LCP，故不全量预加载。
  * 摒弃 Webpack / Vite 庞大的 `node_modules` 依赖链与打包黑盒，所写即所跑，调试零延迟。
  * 没有任何虚拟 DOM 渲染开销，在低性能移动设备上拥有极高帧率和极低能耗。
  * 全部站点发布资源严格收敛于 `public/` 目录，杜绝源码、迁移脚本与测试文件暴露。
  * 其中只有三张公开静态页：`index.html`（应用本体，需登录）、`privacy.html` 与 `terms.html`（隐私政策 / 用户协议）——后两张是**唯一无需登录即可打开**的页面，也是第三方开放平台（如小米运动健康）申请所要求的 https 链接，应用内挂在设置弹层的「关于」入口。
* **后端架构**：**Cloudflare Workers** 边缘无服务器运行环境，全球边缘节点就近调度，冷启动时间 < 5ms。
* **边缘关系存储**：**Cloudflare D1**（基于 SQLite 的高一致性边缘分布式存储，与 Worker 处于极近网络拓扑）。
* **边缘对象存储**：**Cloudflare R2**（v2.5.100 接入）——图片二进制、阅读器书籍正文与 D1 备份快照的存放地，D1 退化为纯元数据，导出/备份体积随之下降；出网流量免费，原生支持 Range 与 ETag，为将来音频与大体积媒体的分发预留了空间。

### 6.2 关键性能与工程亮点

#### ① IndexedDB 异步大容量存储架构 (`db.js`)
* **突破存储配额瓶颈**：针对现代笔记应用高频出现的长篇小说 TXT、海量图片缓存与深度周记，使用 IndexedDB 接管底层持久化，突破浏览器 localStorage 5MB 硬上限。
* **配额感知与平滑降级**：内置 `getStorageEstimate()` 获取实时已用与配额上限；若环境受限则透明回退至 localStorage 切片保护模式，防止单点故障引发丢数据。

#### ② 聚合增量拉取 (`GET /api/sync/pull`) 与 Delta 脏数据推送
* 服务端提供单次聚合接口，在 D1 内部并行并发查询后打包一次性输出，**将移动端全量同步网络往返严格压缩为 1 次 RTT**。
* 本地记录被修改或新建时打上 `_dirty: true` 标记，批量同步时仅上传差异脏数据，最大化节省弱网流量与保护行版本。

#### ③ 工业级 PWA 离线韧性网络
* **Service Worker 模块化全量缓存**：预缓存全部 27 个 ES 业务子模块（含 Trusted Types 收口模块、Wikilinks、Backup、Daily Spark、Evergreen Topics 等）与应用图标，彻底终结了断网时拉取 JS 降级为 HTML 导致的 `Uncaught SyntaxError` 页面白屏崩溃。
* **版本探测与平滑更新**：`version.json` 强绕过 SW 缓存拦截，后台定期毫秒级轻量探活。探测到新版本后静默拉取资源，提供“检测到新版本，点击即时生效”的平滑热更新体验；同一次更新只保留一条底部提示，不再 banner + toast 双提醒。
* **断网感知与自动补偿重连**：监听 `online` / `offline` 事件，断网时安全切换离线提示，重连瞬间自动静默发起云端差异同步，无缝抹平网络颠簸。
* **游标分页拉取（v2.5.165）**：`/api/sync/pull?page_size=100&cursor_<resource>=…` 用 keyset 游标把周记/笔记/收藏/提示词/随手记分页返回，客户端逐页合并后仍写满完整本地缓存；旧客户端不带 `page_size` 时行为完全不变，离线全量口径不被裁成服务器第一页。

og:description，最后播客名兜底），时长解析整块删除（用户明确说「要的是封面/标题/详情，不是时间」），顺带消掉了「播客页时长张冠李戴」的历史坑；
* `bot-outreach.js`：主动关怀的克制层——v2.5.177 起提示词改为熟悉朋友口吻（不称伴侣、不亲密称呼或煽情）；东八区 10:00–22:30 时窗内每天至多一次的随机开口、刚聊完 30 分钟内不插嘴（6 小时内聊过时不再等当天固定时刻，而是在聊完 30–120 分钟内把最近对话作为背景、顺着话题补一句）与只用 3–180 天前旧素材的门禁、模型 SKIP 否决权与概率闸门、账号级开关与逐条发送审计（主动消息同时写进对话记忆并带上出处，用户回一句就能对上）；
* `bot-reminders.js`：定点提醒的状态机——「提醒我 20:00 …」解析成真实时刻（中文数字、今天/明天/早上/晚上、相对时间；解析不了宁可反问也不猜），到点用空 `context_token` 主动开口、30 分钟后只追问一次、超 2 小时标 missed 不补发、发送失败退回 pending 等下一分钟重试；回「完成」才把它沉淀成随手记；与主动关怀分表分开关，一句「别主动找我」关不掉提醒；
* `bot-health.js`：健康打卡（v2.5.155，小米运动健康云服务 A 方案的落地）——把「昨晚睡了 6 小时 20 分，8500 步」这类一句话解析成**一天一行**的结构化数据（新表 `health_daily`，`UNIQUE(user_id, date)` + UPSERT，null 不覆盖旧值），只认显式格式（「健康打卡 / 健康：… / 健康 8500步」），普通聊天一律还给聊天；斤折半成公斤、千分位、越界值（心率 300、999999 步）不写库但在回执里点名；日期一律东八区（「昨晚」归昨天、UTC 深夜算第二天）；发「健康」回最近 7 天汇总，只统计真的记过该字段的天，不拿没记的那天当 0。**只读回显、不写回小米**：这是用户手写的观测记录，云对云（OAuth2 + 订阅回调）仍在评估——那条路要走开发者资质审核，需官网/隐私政策/用户协议三个 https 链接、Android 证书指纹与 APK 包（v2.5.155 已先补齐前两个：公开静态页 `public/privacy.html` 与 `public/terms.html`，由 `tests/security.test.mjs` 守住「无脚本、无内联事件处理器、不引第三方资源、两页互链」）；
* `bot-web.js`：联网检索分流——显式「查一下」与时效性问句才出站（提到自己的记录强制回本地 RAG），搜索取来源、模型按来源作答（v2.5.148 起默认只给结论，用户追问「来源 / 依据 / 哪查的」时才附前 3 条出处，追问直接复用上下文里的出处、不再出站），检索结果 6 小时缓存（v2.5.147 起命中缓存不扣额度）、每人每天 100 次上限（`WEB_DAILY_LIMIT` 可配）与每分钟 2 次突发闸（`WEB_BURST_LIMIT`，护的是一轮 cron 的 55s 收信预算），失败按原因给下一步；上游自 v2.5.146 起主用 DeepSeek 官方 Search（`POST /v1/tools/search`，复用 `LLM_API_KEY`、`ori_question` 带用户原话，返回的 `summary` 与 `site_name`/东八区 `date` 直接进合成提示词——边缘实测 417ms 出 5 条，同一查询 Jina 用 1533ms 且没有日期与站点），Jina 只作回落（`SEARCH_PROVIDER=jina`，或 `SEARCH_API_URL` 指向旧 GET 端点时自动沿用，仍走摘要模式 `X-Respond-With: no-content` + `X-Timeout: 10`），服务端 10s 超时 + 两道客户端死线（检索 20s、合成 20s，合计不占满一轮 cron 收信预算 55s），半截 JSON 一律当没有来源（绝不把 JSON 碎片当摘要喂给模型），时间锚点带星期；**v2.5.149** 起请求带 `need_content`（赛程表/比分这类事实只在网页正文里：实测 8 条约 50 KB、485ms→524ms 几乎不变），候选 5→8、单条上限 1200→3000 字、提示词上下文 5000→12000 字，正文（≥200 字）优先于 summary；相对时间（今天 / 这周周六周日）解析成具体日期并进查询词——检索端不知道「现在」是哪天，这正是「明明有赛程却答没查到」的真凶；并新增时区规则（网页多给当地时区，NBA 默认美东，要换算成北京时间并说明差异）；上游适配层拆到 `bot-search.js`（`workers/src/*` ≤500 行红线），本文件只管闸门、合成、缓存与回复组装；**v2.5.150** 起先花最多 4s 把问题改写成 1–2 条搜索框风格的关键词（`planWebQueries`：没配 `LLM_API_KEY` 就跳过，不额外花调用），与原句合并最多 3 条并行检索（`runWebSearchMulti`：按 URL 去重保留 `rerank_score` 高的副本、按分数降序，部分查询失败不影响整体），闸门同时补上「查看一下」与「比赛 / 开赛 / 下一场 / 下次 / 接下来 / 什么时间 / 哪一场 / 第几场」——2026-10-24 线上「查看一下76人下次比赛是什么时间」既不匹配显式检索词、时效性词表里也没有比赛与时间，于是落进聊天路径把自己上一轮的旧来源复述了一遍（看着像检索结果、还没落缓存）；检索客户端死线 20s→12s（DeepSeek 实测 330–530ms），规划 4s + 检索 12s + 合成 20s = 36s 仍不占满一轮 cron 收信预算；
* `maintenance.js`：按 Cron 表达式分流的定时任务编排——每分钟先派发到点的定点提醒，再跑 ClawBot 轮询；整点第 13 分才跑 UGC 扫描与各类清理。

## 9. 总结与商业价值评价

**Chillin** 展现了一个现代个人心智工具的范本形态：

1. **坚持 Zero-Build 的工程底气**：在前端工具链层层堆叠虚拟 DOM 与沉重捆绑包的今天，Chillin 坚守原生 ES Modules 与 Vanilla CSS，以极其克制优雅的代码实现了秒开、低功耗与无卡顿的极致性能。

3. **真正的数字花园与第二大脑闭环**：不仅拥有三阶生长的常青资产台、网状穿梭的 `[[双向维基]]` 与 Daily Spark 每日心绪，更将数据完全交付给异步大容量 IndexedDB 与定期备份守卫，配合深度定制的边缘 RAG 混合召回，真正让碎片记录汇聚成生命力充沛的私人智慧森林。

无论作为独立开发者私有化部署的心智空间，还是面向知识精英群体的独立商业软件，Chillin 均已建立起极深的产品完成度与体验壁垒。
