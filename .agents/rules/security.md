# 数据安全与防御式编程规范 (Security Rule)

> 本规范约束 Chillin 项目在数据加密、身份鉴权、文件上传、网络请求及富文本渲染层面的安全防线。

---

## 1. 身份认证与密码加密防线

1. **PBKDF2 强哈希算法**：
   * 用户密码必须使用标准 PBKDF2（100,000 次迭代，SHA-256 算法，配合 16 字节独立随机 Salt）；这是 Cloudflare Workers WebCrypto 的硬上限，严禁写成 600,000（边缘会抛 NotSupportedError，登录/注册直接 500）；
   * 旧迭代次数的历史哈希不得强制失效：登录校验成功后须就地重哈希升级到当前迭代数；
   * 严禁明文存储密码，严禁使用 MD5、SHA-1 或单次 SHA-256 等不安全哈希。
2. **时序安全比对 (Timing-Safe Compare)**：
   * Session Token、认证密钥或哈希值的比较必须调用 `timingSafeEqualStr` 进行恒定时间逐字节异或比对；
   * **绝对严禁直接使用 JavaScript 的 `===` 运算符进行密码或 Token 比对**，彻底杜绝基于时序分析的侧信道攻击 (Side-Channel Timing Attack)。

---

## 2. 文件上传与二进制魔数防线

1. **二进制魔数严格嗅探 (Magic-Byte Sniffing)**：
   * 接受任何客户端上传的图片附件前，后端必须在内存中读取前几个字节的二进制魔数：
     * **PNG**: `89 50 4E 47 0D 0A 1A 0A`
     * **JPEG**: `FF D8 FF`
     * **GIF**: `47 49 46 38`
     * **WebP**: `52 49 46 46` ... `57 45 42 50`
   * 坚决拦截利用文件后缀名欺骗上传可执行脚本、SVG 跨站脚本或 Polyglot 恶意载荷的行为。

---

## 3. 服务端出站抓取 (SSRF) 规范 —— 白名单制（v2.5.132 重新引入）

> v2.5.97 曾随外链解析功能一并移除 `security-ssrf.js`（14 组私网/元数据网段、IPv6 内嵌 IPv4、FQDN 尾点归一化等）。
> v2.5.132 为「小宇宙链接速览」重新引入**唯一的**服务端出站抓取点（`workers/src/bot-links.js`），边界比旧实现更紧：

1. **域名白名单**：只允许 `xiaoyuzhoufm.com`（页面）与 `xyzcdn.net`（图床）及其子域；**不做通用外链预览**，白名单之外的 URL 一次都不出站。
2. **协议与端口**：只允许 `https:`，端口必须是 443（显式非默认端口一律拒绝）；拒绝带 userinfo 的 URL。
3. **主机形态**：拒绝 IP 字面量（含 IPv6）、`localhost` / `*.local` 与私网/链路本地/云元数据网段（10 / 127 / 169.254 / 172.16-31 / 192.168）；FQDN 尾点先归一化再比对后缀。
4. **重定向逐跳复核**：必须用 `redirect: 'manual'` 手动跟随，每一跳都重新过一遍白名单（最多 3 跳），绝不把重定向目标交给 fetch 自动跟随。
5. **超时与体积**：`AbortSignal.timeout(6000)`；HTML ≤ 512KB、封面 ≤ 4MB，读取时按上限截断并 `cancel()`，绝不无界读进内存。
6. **降级不假装**：任何一步失败都如实告知用户并给出「记录：<链接>」的兜底路径，抓不到的内容绝不入库。
7. **可选代读（v2.5.137，方案 B）**：直连被出口 IP 封（线上常态是 403）时，若配置了 `LINK_READER_API_KEY`，才允许把**白名单内**的目标 URL 交给第三方读取服务代读一次（默认 `https://r.jina.ai`，可用 `LINK_READER_URL` 覆盖；仅接受 https、拒绝带 userinfo 的地址）；密钥只从环境读取，绝不写进代码或日志；**未配置密钥时这条路径完全关闭**（一次请求都不多发）。代读返回的 JSON 元数据（Microlink 形状）里，封面同样必须过图床白名单，否则丢弃——绝不热链第三方图片。请求一律只声明 `Accept: text/html`（v2.5.138：带上 `application/json` 时 Jina 会回 JSON，而 JSON 里没有封面字段）；若服务仍返回 JSON，正文优先取 `data.html` / `data.content` 里内嵌的 HTML 交给页面解析器，JSON 字段只作没有封面时的元数据回落。

## 4. 前端防存储型 XSS (DOMPurify 过滤)

1. **富文本注入白名单**：
   * 任何来自用户输入、外链提取或数据库持久化文本在通过 `innerHTML` 渲染前，必须经过 `DOMPurify.sanitize()` 进行白名单过滤清洗；
   * 避免用户或第三方外链注入 `<script>`、`onload`、`javascript:` 等恶意代码。
